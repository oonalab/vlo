Vlo documentation ​

Durable execution for workflows and AI agents, as a library on the database you already run. Vlo keeps long-running work alive through crashes and restarts: an agent on its fortieth step, a render that takes three hours, an approval that takes two days.

What you getRead more
TinyA 298 KB kernel inside your process. No cluster, no broker, no service to stand up.Why Vlo
PerformantOne transaction per step, and a resume that costs the same at 38 events and at 20,000.Performance
ReliableNothing is acknowledged before it is saved, and every checkpoint is hash-checked.Reliability
EfficientA waiting run holds no compute. An agent that reaches its budget parks instead of burning money.Why Vlo
Built for the edgeA kernel with no I/O that runs anywhere wasm runs. The edge host is not built yet.Status and roadmap

All five come from one design principle: a workflow is a pure reducer, (state, event) → (state, commands). An event comes in, new state and commands come out, and both are saved in one database transaction. Between events a run is only rows in your Postgres or a SQLite file, so nothing has to be kept alive, captured or replayed.

Generated API reference ​

Both are published with these pages at https://oonalab.github.io/vlo/.

  • TypeScript (@oona/vlo and its /host, /agent and /testing entries): oonalab.github.io/vlo/api/. TypeDoc writes a page for every exported symbol into docs/api/. Build it locally with pnpm --filter @oona/vlo docs:api; the output is not committed, so you will not find it in a checkout.
  • Rust (vlo-types, vlo-kernel, vlo-kernel-wasm, vlo-traits): oonalab.github.io/vlo/rustdoc/. Build it locally with cargo doc --workspace --no-deps --open from the repository root.

Conventions used in these pages ​

  • Paths are relative to the repository root unless they start with src/, in which case they are relative to sdk/ts/sdk/.
  • Wire fields are snake_case (cost_micro_usd); authoring options are camelCase (costMicroUsd). The wire form is what you see in the journal and on the HTTP API.
  • Every instant is a millisecond Unix epoch and every such column or field ends in _ms.
